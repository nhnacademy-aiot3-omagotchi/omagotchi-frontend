# Timer Frontend Backend Integration Prompt

## Purpose

현재 프론트엔드의 학습 Timer UI를 백엔드 Timer API와 연결하는 작업이다.

핵심 목표는 기존 Timer UI와 학습 흐름을 유지하면서, 학습 시간 확정과 세션 상태 판단을 Backend Response 기준으로 전환하는 것이다.

## Frontend Ownership Map

Timer 담당자는 아래 파일 범위 안에서 작업한다.

### User Timer Area

HTML:

- `src/main/resources/templates/pages/app/home.html`

CSS:

- `src/main/resources/static/css/home.css`
- `src/main/resources/static/css/homeAttendance.css`, 출석 상태와 Timer 표시가 명세상 같이 바뀌는 경우만
- `src/main/resources/static/css/homeAttendanceSync.css`, 출석/타이머 동기화 표시가 명세상 필요한 경우만

JS:

- `src/main/resources/static/js/home/timer.js`
- `src/main/resources/static/js/home.js`, Timer module 초기화나 홈 상태 재조회 연결이 필요한 경우만
- `src/main/resources/static/js/home/level.js`, Timer 종료 후 레벨/EXP 갱신 연결이 필요한 경우만
- `src/main/resources/static/js/home/attendance.js`, Timer와 출석 상태가 Backend 명세상 연결되는 경우만
- `src/main/resources/static/js/api.js`, Timer API helper 추가가 필요한 경우만

Controller:

- `src/main/java/site/omagotchi/frontend/presentation/MainPageController.java`

주의:

- `/home` URL은 유지한다.
- `home.html`의 기존 Timer DOM과 `data-timer-*` 셀렉터는 유지한다.
- Timer UI 구조를 새로 만들지 말고, 기존 버튼/표시 영역에 Backend state를 연결한다.
- Controller는 view name 연결만 담당한다. 학습 시간 계산, 세션 상태 판단, 권한 판단을 Controller에 넣지 않는다.

### Manager Dashboard Timer Area

관리자 대시보드에서 학습 시간, 현재 학습 중 여부, 세션 수를 표시해야 하는 경우에만 작업한다.

HTML:

- `src/main/resources/templates/pages/manager/managerDashboard.html`

CSS:

- `src/main/resources/static/css/managerDashboard.css`

JS:

- `src/main/resources/static/js/managerDashboard.js`
- `src/main/resources/static/js/api.js`, manager timer API helper 추가가 필요한 경우만

Controller:

- `src/main/java/site/omagotchi/frontend/presentation/ManagerPageController.java`

주의:

- 기존 `overview`, `members`, `attendance` 패널 안에서 필요한 값만 연결한다.
- 기존 `data-dashboard-panel`, `data-dashboard-tab`, `data-summary-*` 셀렉터는 변경하지 않는다.
- Timer 통계를 위해 관리자 대시보드 레이아웃을 새로 만들지 않는다.

### Out Of Scope

아래 파일은 Timer 담당자가 임의 수정하지 않는다.

- Space 전용 화면: `templates/pages/app/space.html`
- Space 전용 JS/CSS: `static/js/space.js`, `static/js/spaceRoom.js`, `static/css/space.css`, `static/css/spaceRoom.css`
- 인증 화면: `templates/pages/auth/*`
- 회원가입/로그인 JS: `static/js/login.js`, `static/js/register.js`, `static/js/username.js`
- 캐릭터 선택 화면: `templates/pages/onboarding/characterSelector.html`
- 에러 화면: `templates/error/*`
- 공통 레이아웃: `templates/layouts/managerLayout.html`, 단 관리자 레이아웃 자체 변경 요구가 명시된 경우는 예외

## Common Rules

### Scope

- 기존 Timer UI를 유지한다.
- 홈 화면의 타이머 위치, 버튼, 표시 형식, 상태 메시지 흐름을 임의로 바꾸지 않는다.
- 기존 라우팅과 홈 화면 구조를 변경하지 않는다.
- 현재 UX에서 필요한 데이터만 Backend Response로 치환한다.
- Backend API 명세에 없는 타이머 기능은 구현하지 않는다.
- API 응답 필드명이 기존 프론트 상태명과 다르면 프론트 내부에 매핑 레이어를 둔다.

### Data Handling

- 새로운 Mock 데이터 생성 금지.
- 기존 local/session storage 기반 임시 학습 기록은 제거하거나 API 실패 시 fallback 용도로만 분리한다.
- 학습 세션 시작, 진행, 일시정지, 종료, 요약은 Backend Response 기준으로 처리한다.
- null, 진행 중 세션 없음, 이미 실행 중, 이미 종료됨, 권한 없음, 서버 시간 불일치 상태를 반드시 UI에서 처리한다.
- Frontend에서 학습 시간을 최종 확정하지 않는다.

### Authorization

- 기본적으로 기존 `src/main/resources/static/js/api.js`의 `window.OmagotchiApi` helper를 사용한다.
- 현재 프론트는 `/bff/v1` same-origin 호출을 기준으로 하므로, 화면 JS에서 access token을 직접 꺼내 붙이지 않는다.
- Backend를 직접 호출해야 하는 명세가 별도로 주어진 경우에만 REST API 요청에 `Authorization: Bearer {accessToken}`을 사용한다.
- 권한 판단은 Backend가 JWT와 Membership 기준으로 수행한다.
- Frontend는 버튼 상태, 안내 문구, 실패 메시지 같은 UX 처리만 담당한다.

금지:

- `userId` 직접 전달
- `authorUserId` 전달
- `role`, `admin`, `isManager` flag 전달
- 클라이언트에서 권한 우회
- Backend에 없는 학습 세션 데이터 임의 생성

## Timer API Integration

### Required Flow

페이지 진입:

```text
홈 진입
↓
현재 진행 중인 Timer Session 조회
↓
Backend Response 기준으로 UI 상태 복원
↓
실행 중이면 화면 표시용 tick 시작
↓
진행 중 세션이 없으면 대기 상태 표시
```

시작:

```text
사용자가 시작 버튼 클릭
↓
Timer Start API 호출
↓
Backend가 생성한 session id, startedAt, status 수신
↓
Response 기준으로 UI 갱신
```

종료:

```text
사용자가 종료 버튼 클릭
↓
Timer Stop API 호출
↓
Backend가 확정한 duration, endedAt, reward, quest update 수신
↓
Response 기준으로 UI 갱신
↓
필요 시 홈/퀘스트/레벨 상태 재조회
```

### Display Rules

- 화면의 초 단위 증가는 UX 표시용이다.
- 저장되는 학습 시간은 Backend가 확정한 값을 사용한다.
- 새로고침 후에는 진행 중 세션 조회 결과로 Timer UI를 복원한다.
- 브라우저 탭 비활성화, 절전, 네트워크 지연으로 생긴 시간 차이는 Backend Response로 보정한다.
- Timer 종료 후 표시되는 학습 시간, EXP, 퀘스트 진행도는 Backend Response 또는 재조회 결과를 사용한다.

### Session Status

Backend API 명세에 정의된 상태값만 사용한다.

예상 상태가 명세에 있다면 그대로 매핑한다.

```text
IDLE
RUNNING
PAUSED
ENDED
EXPIRED
```

주의:

- 위 상태값은 예시다.
- Backend 명세에 없는 상태값을 Frontend에서 새로 만들지 않는다.
- `PAUSED`가 Backend에 없으면 일시정지 UI를 구현하지 않는다.

## Home / Gamification Sync

Timer는 홈, 퀘스트, 레벨과 연결된다.

- Timer 종료 후 학습 시간 요약을 Backend 기준으로 표시한다.
- Quest 진행도는 Frontend에서 계산하지 않는다.
- EXP, Level, Required XP, Advancement Stage는 Gamification API 결과를 사용한다.
- 보상 수치, 레벨업 여부, 퀘스트 완료 여부는 Backend Response 기준으로 표시한다.
- Timer 종료 후 필요한 경우 다음 데이터를 재조회한다.

```text
GET /gamification/home
GET /gamification/quests/daily
GET /gamification/progression
```

## Manager Dashboard Constraints

관리자 대시보드에서 Timer 관련 데이터를 보여줘야 하는 경우 기존 틀 안에서만 연결한다.

유지할 것:

- 기존 관리자 레이아웃
- 사이드바 탭 구조
- 출결/구성원/통계 패널 배치
- 기존 CSS 클래스와 `data-dashboard-*` 셀렉터

허용:

- 학습 시간, 현재 학습 중 여부, 오늘 세션 수를 Backend Response로 표시
- Loading, Empty, Error 상태 표시
- 서버 validation 또는 권한 오류 메시지 표시

금지:

- 관리자 대시보드 전체 레이아웃 재작성
- Timer 통계를 Frontend에서 직접 집계
- 사용자별 학습 시간 합산을 Frontend에서 계산
- 관리자 권한을 Frontend에서 계산
- 관리자용 `userId`, `role`, `admin flag`를 request body에 넣기

## API Layer Convention

- API 호출 코드는 한 곳에서 관리한다.
- Timer UI 코드 안에 `fetch`를 직접 흩뿌리지 않는다.
- 기존 `src/main/resources/static/js/api.js`의 `window.OmagotchiApi` 패턴을 우선 사용한다.
- Timer API service와 Timer UI 렌더링 코드를 분리한다.
- Backend Response를 Timer view state로 변환하는 매핑 함수를 둔다.

권장 구조:

```text
static/js/api.js
static/js/home/timer.js
static/js/home.js
static/js/managerDashboard.js
```

단, 실제 파일 추가 여부는 현재 프로젝트 구조와 Backend API 명세를 보고 결정한다.

## Required States

Timer UI는 다음 상태를 처리한다.

- Loading
- Idle
- Running
- Paused, Backend 명세에 있는 경우만
- Ending
- Ended
- Error
- Unauthorized
- Forbidden
- Session Not Found
- Already Running
- Already Ended

## Do Not

- Frontend timer 값을 기준으로 학습 시간을 확정하지 말 것.
- `Date.now()` 차이만으로 최종 duration을 저장하지 말 것.
- 종료 API 성공 전 세션을 완료 처리하지 말 것.
- Backend가 reject한 세션을 성공 처리하지 말 것.
- 새로고침 후 local/session storage 값만으로 Timer 상태를 복원하지 말 것.
- Timer 종료 보상, XP, 퀘스트 완료 여부를 Frontend에서 계산하지 말 것.
