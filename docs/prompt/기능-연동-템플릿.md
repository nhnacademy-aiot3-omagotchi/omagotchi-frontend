# [기능명] Backend Integration Prompt Template

> 사용 전 `[기능명]`, Endpoint, DTO와 허용 파일을 실제 값으로 바꾼다.
> 이 문서만 단독으로 사용하지 않는다. AI Agent는 먼저
> [Backend Integration AI 공통 보호 규칙](공통-보호규칙.md)을 읽고 그대로 따라야 한다.
> 기능별 adapter·Controller와 보존 계약은
> [Frontend ↔ Backend 기능별 연결 지도](../integration/frontend-backend-connection-map.md)에서 확인한다.

## 작업 목적

기존 `[기능명]` UI와 화면 흐름을 유지하면서 확정된 Backend API를 View BFF를 통해
연결한다. UI 재설계, 인증 구조 변경, 공통 컴포넌트 리팩터링은 이 작업 범위가 아니다.

## 확정된 API 계약

아래 항목에 빈칸이 있거나 실제 API 문서와 다르면 구현을 중단하고 담당자에게 질문한다.

```text
Browser BFF Endpoint: [예: GET /bff/v1/...]
Domain Endpoint: [예: GET /api/v2/...]
Request DTO: [문서 또는 클래스 경로]
Response DTO: [문서 또는 클래스 경로]
Success Status: [예: 200]
Error Status: [예: 400, 401, 403, 404, 409, 503]
```

Browser 코드에는 Domain `/api/v1/**`, `/api/v2/**` 경로를 직접 작성하지 않는다.
`window.OmagotchiApi` → `/bff/v1/**` → View BFF Client 순서를 유지한다.

## 허용된 수정 범위

이 기능을 연결하는 데 필요한 아래 파일만 최소 수정한다.

```text
src/main/resources/static/js/api.js
[기능 전용 기존 JavaScript Controller 경로]
[기능 전용 View BFF Controller 경로]
[기능 전용 Client·DTO·Error 경로]
[기능 API 계약 문서 경로]
```

목록 밖의 파일이 필요하면 먼저 변경 이유와 영향 범위를 보고하고 승인을 기다린다.

## 반드시 보존할 계약

```text
[기능이 사용하는 data-* 목록]
[기능이 사용하는 class 또는 root 목록]
[기존 이벤트 위임 함수]
[로딩·빈 값·오류 표시 root]
```

- `src/main/frontend/ui/**`, Storybook, 공통 CSS와 생성된 `home-app.js`를 수정하지 않는다.
- Login, Register, Security, Session, Redis, JWT와 Identity 코드를 수정하지 않는다.
- 기존 Dialog, Tabs, 모바일 Layout과 버튼 위치를 변경하지 않는다.
- Story mock을 실제 앱으로 import하지 않는다.
- API 실패를 localStorage·sessionStorage 또는 임시 값으로 성공 처리하지 않는다.
- 폐기된 실시간 채팅, GLOBAL·COHORT 채팅 탭과 메시지 입력창을 복원하지 않는다.
- AI 도우미 작업이면 [Home AI 도우미 구현 Prompt](AI-도우미.md)의 Tool·권한·개인정보 규칙을 함께 적용한다.

## 구현 순서

1. `git status --short`와 관련 파일의 기존 변경을 확인한다.
2. `window.OmagotchiApi`에서 기존 `[기능명]` 호출 경계를 찾는다.
3. BFF Controller·Client·DTO의 실제 계약을 확인한다.
4. Response를 기존 UI State로 바꾸는 순수 mapping 함수를 한 곳에 둔다.
5. Loading, Empty, Success, Error와 권한 없음 상태를 기존 DOM에 연결한다.
6. API가 완성된 범위에서만 `[API-REPLACE]` fallback을 제거한다.
7. 기존 화면과 다른 Home 기능의 회귀 테스트를 실행한다.

## 완료 조건

- 확정된 API 응답만 Source of Truth로 사용한다.
- 기존 `data-*`, class, Dialog·Tabs와 모바일 배치를 보존한다.
- 잘못되거나 비어 있는 응답을 성공으로 처리하지 않는다.
- 변경 파일이 위 허용 범위를 벗어나지 않는다.
- 변경한 Endpoint·DTO·파일·테스트와 남은 Prototype을 완료 보고에 적는다.
