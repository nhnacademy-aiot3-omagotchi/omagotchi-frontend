# 관리자 공간·센서 Chart.js 연동 가이드

> 상태: 구현 가이드·작업 Prompt
>
> 대상: 관리자 공간·센서 React Island에 실제 센서 시계열 차트를 연결하는 개발자
>
> 필수: 작업 전 [Backend Integration AI 공통 보호 규칙](공통-보호규칙.md)을 읽고 따른다.

## 1. 작업 목적

관리자 대시보드의 기존 레이아웃과 `공간·센서` React Island를 유지하면서, 현재
Chart.js 자리 표시 영역에 Backend 센서 시계열 데이터를 표시한다.

이 작업은 화면을 새로 설계하는 작업이 아니다. Storybook과 실제 관리자 대시보드에
연결된 `SensorWorkspace`의 DOM·필터·센서 추가 흐름을 보존하고 차트 데이터 조회와
Chart.js 생명주기만 연결한다.

## 2. 현재 화면 구조

```text
/manager-dashboard?panel=sensors
└─ 관리자 공통 Layout (Thymeleaf)
   └─ 공간·센서 Panel
      └─ SensorWorkspace React Island
         ├─ 대시보드 Tab
         │  ├─ 공간 선택: 실습실 / 회의실 / 도서관
         │  ├─ 기간 선택: 일 / 주 / 월
         │  ├─ 월 이동: 이전 월 / 현재 월 / 다음 월
         │  ├─ 활성 센서의 측정 항목별 Chart Card
         │  └─ 센서 감사 로그
         └─ 센서 목록 Tab
            ├─ 상태 Filter·검색
            ├─ 센서 추가·설정 Overlay
            └─ 센서 목록
```

센서 한 대가 온도와 습도를 측정하면 Chart Card가 두 개 생성된다. Chart의 식별 단위는
`sensor.id + metric`이다. 센서를 추가하거나 측정 항목을 변경하면 React가 카드 개수를
자동으로 다시 계산한다.

## 4. 현재 Chart.js Mount 계약

각 Chart Card에는 실제 `<canvas>`가 이미 존재한다.

```html
<article class="sensor-chart-card"
         data-sensor-id="lab-environment-01"
         data-metric="temperature">
  <canvas class="sensor-chart-canvas"
          data-sensor-chart-canvas
          data-sensor-id="lab-environment-01"
          data-metric="temperature"></canvas>
</article>
```

- `data-sensor-id`: 센서 식별자
- `data-metric`: `temperature`, `humidity`, `co2` 중 하나
- `data-sensor-chart-canvas`: Chart.js Mount 지점
- `.sensor-chart-mount`: 아직 실제 Chart가 연결되지 않았음을 보여주는 자리 표시 문구

DOM을 전역 검색해서 Chart를 생성하지 말고 React Component와 `ref` 안에서 Chart.js
Instance를 생성·폐기한다. 전역 검색은 Tab 전환, 센서 추가, 필터 변경 시 Instance가
중복될 수 있다.

## 5. Chart.js 연결 방법

`SensorWorkspace.jsx`의 현재 `ChartPlaceholder`를 작은 `SensorChart` Component로
분리하는 방식을 권장한다.

```jsx
function SensorChart({ sensor, metric, period, month, series }) {
  const canvasRef = useRef(null);

  useEffect(() => {
    if (!canvasRef.current || !series || !window.Chart) return undefined;

    const chart = new window.Chart(canvasRef.current, {
      type: "line",
      data: {
        labels: series.labels,
        datasets: [{
          label: series.label,
          data: series.values,
          borderColor: "#2f6fed",
          backgroundColor: "rgba(47, 111, 237, 0.12)",
          fill: true,
          tension: 0.35
        }]
      },
      options: {
        responsive: true,
        maintainAspectRatio: false
      }
    });

    return () => chart.destroy();
  }, [sensor.id, metric, period, month, series]);

  return <canvas ref={canvasRef} data-sensor-chart-canvas />;
}
```

반드시 지킬 것:

- Effect Cleanup에서 `chart.destroy()`를 호출한다.
- Sensor, Metric, 기간이 바뀌면 기존 Instance를 폐기하고 다시 생성한다.
- 한 Canvas에 Chart Instance를 중복 생성하지 않는다.
- `window.Chart`가 없을 때 Page 전체를 실패시키지 않고 오류 상태를 표시한다.
- Canvas 크기는 기존 `.sensor-chart-canvas` Style을 사용한다.
- Chart를 연결한 Card에서는 `.sensor-chart-mount` 자리 표시 문구를 숨긴다.

Chart.js 4.5.1은 관리자 Page에서 React Bundle보다 먼저 로드된다. 별도 CDN이나 다른
Chart.js Version을 추가하지 않는다.

## 6. Filter와 조회 조건 연결

현재 UI 상태는 다음 의미를 가진다.

| UI 값 | 의미 |
| --- | --- |
| `space=lab` | 실습실 |
| `space=meeting` | 회의실 |
| `space=library` | 도서관 |
| `period=day` | 최근 24시간 |
| `period=week` | 최근 1주 |
| `period=month` | 선택한 월 단위 |
| `month=1..12` | 월 조회 시 선택 월 |

공간 또는 기간을 변경하면 해당 조건의 시계열을 다시 조회한다. 월 선택은 1월부터
12월까지만 이동하며, 월 조회가 아닐 때 `month` 값을 요청에 임의로 포함하지 않는다.

요청이 빠르게 연속 변경될 수 있으므로 이전 요청을 `AbortController`로 취소하거나,
마지막 요청만 화면에 반영한다. 느린 이전 응답이 최신 Filter 결과를 덮어쓰면 안 된다.

## 7. 데이터 경계

Browser에서 Domain Service를 직접 호출하지 않는다.

```text
SensorWorkspace
→ window.OmagotchiApi.manager의 센서 조회 함수
→ /bff/v1/**
→ Frontend BFF
→ Sensor 데이터를 소유한 Domain Service
```

Backend API 계약이 확정되기 전에는 `api.js`에 추정 경로를 추가하지 않는다. 계약이
확정되면 `window.OmagotchiApi.manager` 아래에 센서 시계열 조회 함수를 한 번만 추가하고,
React Component 안에 `fetch()`를 직접 작성하지 않는다.

아래 구조는 Backend Wire DTO가 아니라 Chart가 사용하기 좋은 **화면 내부 Model 예시**다.

```json
{
  "sensorId": "lab-environment-01",
  "metric": "temperature",
  "unit": "°C",
  "labels": ["14시", "15시", "16시"],
  "values": [24.1, 24.5, 24.3],
  "average": 24.3,
  "threshold": 26,
  "minimum": 23.8,
  "maximum": 24.8
}
```

Backend Response가 다르면 Adapter 함수에서 이 Model로 변환한다. Backend DTO 필드명을
Chart option이나 CSS class에 직접 결합하지 않는다.

## 8. 센서와 Chart 생성 규칙

- 현재 선택한 공간의 센서만 표시한다.
- `active=true`인 센서만 Chart를 생성한다.
- 센서의 `metrics` 배열 항목마다 Chart 하나를 생성한다.
- 온도·습도 센서는 Chart 두 개를 생성한다.
- 비활성화된 센서는 센서 목록에는 남지만 대시보드 Chart에서는 제외한다.
- Sensor가 없으면 현재 빈 상태 UI를 유지한다.
- Sensor 추가·수정 후 Backend 성공 응답을 받은 다음 목록과 Chart를 갱신한다.
- Backend 실패를 로컬 성공 상태로 숨기지 않는다.

## 9. 화면 상태

각 Chart Card는 다음 상태를 구분한다.

- Loading: 시계열 조회 중
- Ready: Chart, 평균, 기준값, 집계 조건 표시
- Empty: Sensor는 있지만 선택 기간에 측정값 없음
- Error: 조회 실패와 재시도 안내
- Warning: 임계값 초과 구간과 초과 횟수 표시

전체 Sensor 조회 실패와 특정 Chart 한 개의 조회 실패를 구분한다. 특정 Sensor 응답이
실패했다고 다른 정상 Chart까지 제거하지 않는다.

## 10. Storybook과 실제 Runtime 구분

- Storybook의 Sensor와 감사 로그는 UI·페이지네이션 검증용 Mock이다.
- 실제 `/manager-dashboard`는 `sensorsPanel.js`가 현재 기수 Context를 React Island에 전달한다.
- 실제 Runtime에서 Storybook Mock을 Source of Truth로 사용하지 않는다.
- Storybook을 수정해도 실제 Page Bundle은 자동 갱신되지 않으므로 `npm run build:home`을 실행한다.
- 실제 Page 수정 후에도 `npm run build-storybook`으로 Story 회귀를 확인한다.

## 12. 금지 사항

- 생성된 `manager-sensors-app.js` 직접 수정 금지
- React Component 내부 Domain URL 하드코딩 금지
- Browser Token 저장·전달 금지
- 새 Chart.js CDN 또는 중복 Version 추가 금지
- Canvas 전역 검색 후 Instance 방치 금지
- Backend 계약 없는 Request Field·기간 값 추정 금지
- API 실패 시 Storybook Mock 또는 Browser 저장소로 성공 처리 금지
- Chart 작업을 이유로 관리자 공통 Layout·Sidebar·다른 Panel 수정 금지
