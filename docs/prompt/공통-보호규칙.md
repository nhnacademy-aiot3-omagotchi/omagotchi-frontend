# Backend Integration AI 공통 보호 규칙

- 상태: Backend 연동 Prompt 필수 선행 지시문
- 적용 대상: `view` 저장소에서 Backend API를 연결하는 모든 사람과 AI Agent

## 사용 방법

기능별 Prompt보다 이 문서를 먼저 제공한다. AI Agent는 작업을 시작하기 전에 이 문서와
기능별 Prompt를 모두 읽고, 두 문서의 보호 범위 안에서만 수정한다.

이 문서는 API 구현 방법보다 우선하는 Frontend 보호 계약이다. Backend 명세 또는 현재
코드만으로 해결할 수 없어 이 계약을 변경해야 한다면 임의로 진행하지 말고 Frontend
담당자에게 변경 필요성과 영향 파일을 먼저 알린다.

## 현재 Frontend 기준선

- Branch: `feature/mobile-ui`
- Home UI: React Island와 기존 Vanilla JavaScript가 공존
- 기능 연결: 기존 `home.js`와 `home/*.js`가 `data-*` DOM 계약 사용
- 공통 UI: `src/main/frontend/ui/`
- UI 검증: Storybook
- 접근성 동작: Radix UI `GameDialog`, `GameTabs`
- 제한적 전환 효과: Motion
- 실제 Home 적용: 도움말·설정 Dialog, 진행 Tabs
- 공통 스타일: 표준 CSS 기반 자체 디자인 시스템
- Browser API 경계: 같은 Origin의 `/bff/v1/**`
- 인증: HttpOnly Session Cookie, Browser에 JWT 원문 노출 금지

## 작업 시작 전 필수 확인

1. `git status --short`로 기존 변경사항을 확인하고 다른 사람의 변경을 덮어쓰지 않는다.
2. 기능별 Prompt와 관련 API 명세를 읽는다.
3. [기능별 연결 지도](../integration/frontend-backend-connection-map.md)에서 adapter·Controller·보존 계약을 확인한다.
4. 현재 `window.OmagotchiApi`와 해당 기능 Controller의 호출 흐름을 확인한다.
5. 수정 전에 사용 중인 `data-*`, class, 이벤트 위임과 Story를 검색한다.
6. API Path, Method, Request·Response DTO가 불명확하면 추측 구현을 중단한다.

## 수정 금지 또는 사전 협의 경로

Backend 연동만을 이유로 다음 경로를 수정하지 않는다.

```text
.storybook/**
src/main/frontend/ui/**
src/main/frontend/**/*.stories.*
src/main/resources/static/css/ui/**
docs/home-ui/**
docs/adr/**
src/main/resources/static/js/home-react/home-app.js
package.json
package-lock.json
vite.config.js
```

- `home-app.js`는 Vite 생성물이므로 직접 편집하지 않는다.
- Storybook의 mock, Story args와 시각 검증 데이터를 실제 서비스에서 import하지 않는다.
- Radix UI, Motion, Storybook과 CSS 라이브러리를 추가·제거·교체하지 않는다.
- `design-system.css` Token, 공통 class와 반응형 기준을 API 연결 때문에 재작성하지 않는다.
- React UI의 DOM, class와 `data-*`를 바꿔야 한다면 먼저 Frontend 담당자와 협의한다.

인증 기능 연동 작업이 아니라면 다음 영역도 수정하지 않는다.

```text
SecurityConfig
AuthenticationProvider·Filter·Handler
Login·Register Controller와 Thymeleaf Form
Session·Redis·JWT relay 공통 설정
Identity Service 연동 코드
```

## Backend 연동 시 허용되는 기본 범위

기능별 Prompt에서 별도로 허용한 파일을 우선하며, 일반적으로 다음 범위 안에서 최소
변경한다.

- `src/main/resources/static/js/api.js`의 기능별 API adapter
- 기존 `src/main/resources/static/js/home/*.js` 기능 Controller의 데이터 매핑과 상태 처리
- 기능 전용 Java BFF Controller, Client, DTO와 오류 매핑
- API 계약과 연동 결과를 설명하는 Backend 연동 문서

React 컴포넌트 안에 `fetch`를 직접 추가하지 않는다. Browser 요청은
`window.OmagotchiApi` 또는 기능별 API helper 한 곳을 통과시킨다.

## API Path와 Version 규칙

- React, Storybook과 UI 컴포넌트에 Domain Service의 `/api/v1`, `/api/v2` 경로를 직접
  작성하지 않는다.
- Browser는 `/bff/v1/**`만 호출한다.
- Domain API Version과 Gateway route 변경은 Frontend BFF Client·설정 계층에서 흡수한다.
- v1과 v2가 공존하는 동안 호환 여부를 추측하지 않는다.
- API 명세에 없는 Field, Query Parameter와 Status를 만들지 않는다.

```text
React·Vanilla UI
  → window.OmagotchiApi
  → Frontend /bff/v1/**
  → Domain Client·Gateway route
  → Domain /api/v1 또는 /api/v2
```

## UI와 상태 보호 규칙

- 현재 화면 구조, 버튼 위치, Dialog, Tabs와 모바일 Layout을 유지한다.
- 기존 `data-*` 속성을 삭제하거나 이름을 바꾸지 않는다.
- API Response와 화면 State가 다르면 별도 mapping 함수로 변환한다.
- Loading, Empty, Success, Error와 권한 없음 상태만 기존 UI에 연결한다.
- Backend Response를 Source of Truth로 사용한다.
- Browser 저장소 값으로 API 실패를 성공처럼 보정하지 않는다.
- API가 완성되지 않았다는 이유로 기존 Prototype fallback을 새로 확대하지 않는다.
- 기존 Prototype fallback 제거는 관련 BFF Endpoint가 정상 응답하고 회귀 검증이 끝난 뒤
  별도 변경으로 수행한다.

## Git과 변경 범위 규칙

- 관련 없는 파일 Formatting, Rename, 이동과 대규모 리팩터링을 하지 않는다.
- 기존 변경을 `git reset`, `git restore`, `git checkout --`로 삭제하지 않는다.
- Dependency 설치와 Lockfile 갱신을 하지 않는다.
- 기능 하나의 API adapter·mapping·상태 처리만 한 변경에 포함한다.
- 충돌이 발생하면 Frontend UI 파일을 임의 선택해 덮어쓰지 않는다.

## 반드시 멈추고 질문할 조건

- API Path, Version, Method 또는 DTO가 문서마다 다르다.
- 인증·인가·JWT·Session 공통 구조 변경이 필요하다.
- `src/main/frontend/ui/**` 또는 공통 CSS를 바꾸지 않으면 연결할 수 없다.
- 기존 `data-*` 계약을 제거해야 한다.
- Backend에 없는 상태나 성공 데이터를 Frontend에서 생성해야 한다.
- 다른 사람의 미커밋 변경과 같은 파일이 겹친다.
