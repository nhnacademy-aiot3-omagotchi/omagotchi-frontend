# Space / Team Backend Integration Prompt

> 필수: 이 Prompt를 실행하기 전에
> [Backend Integration AI 공통 보호 규칙](공통-보호규칙.md)을 먼저 읽고 그대로 따른다.
> 공통 보호 규칙과 이 문서가 충돌하면 더 좁고 안전한 수정 범위를 적용한다.

## 작업 목적

공간과 팀 관련 화면을 현재 프론트 구조 안에서 Backend API와 연결한다.

이 작업의 핵심은 Space / Team의 소유권, 참여 가능 여부, 관리 가능 여부를 Frontend에서 추론하지 않고 Backend Response 기준으로 표시하는 것이다.

## 작업 지시

아래 지시를 그대로 따른다.

현재 프론트엔드는 이미 화면 틀과 리뉴얼 방향이 정해져 있다.
Home 화면의 메뉴/오버레이 계열 UI는 React island와 기존 `home.js`의 `data-*` 계약을 같이 사용하는 방향으로 전환 중이다.
따라서 이 작업은 새 화면을 만드는 작업이 아니라, **현재 만들어진 Space / Team 화면 구조와 Home React island 계약 안에서 Backend API만 연결하는 작업**이다.

### 절대 지킬 것

- 현재 HTML 또는 Home React island 구조를 임의로 갈아엎지 말 것.
- 기존 `data-home-overlay`, `data-space-room-app`, Space/Team 관련 `data-*` DOM 계약을 깨지 말 것.
- 현재 CSS 구조를 임의로 합치거나 대규모 재작성하지 말 것.
- 현재 JS 모듈 구조를 무시하고 새 흐름을 만들지 말 것.
- 현재 화면 이동, 탭, 버튼, 모달, 리스트 흐름을 임의로 변경하지 말 것.
- 관리자 대시보드의 기존 틀을 Space/Team 연동 때문에 건드리지 말 것.
- API 연결에 필요한 최소 변경만 할 것.
- UI 변경이 필요하면 기존 클래스와 구조 안에서 상태 표시만 추가할 것.
- Backend API 명세에 없는 기능을 상상해서 만들지 말 것.
- Mock을 새로 만들지 말 것.
- `.storybook/**`, `src/main/frontend/ui/**`, Story 파일과 `css/ui/**`를 수정하지 말 것.
- `GameDialog`, `GameTabs`, Radix UI, Motion과 Storybook 구성을 변경하지 말 것.
- Domain `/api/v1`, `/api/v2` 경로를 React 또는 Space·Team UI에 직접 작성하지 말 것.
- Browser API 호출은 기존 `window.OmagotchiApi`와 `/bff/v1/**` 경계를 유지할 것.
- `home-app.js` 생성물을 직접 수정하지 말 것.
- Space·Team 연동 범위를 넘어 인증·Session·JWT·Identity 코드를 수정하지 말 것.

### 작업 방식

1. 현재 파일 구조를 먼저 파악한다.
2. 기존 Space / Team 관련 DOM, CSS class, JS 상태 흐름을 유지한다.
3. API 호출 함수만 service/helper 단위로 분리한다.
4. Backend Response를 기존 화면 상태에 매핑한다.
5. 성공/실패/로딩/빈 상태만 UI에 반영한다.
6. 테스트 또는 수동 확인 가능한 변경만 남긴다.

## 공통 작업 규칙

- 현재 존재하는 화면, 라우팅, 컴포넌트 구조를 기준으로 API를 연결할 것.
- 화면 흐름을 임의로 변경하지 말 것.
- 기존 UI, 기능 흐름과 DOM 계약을 보존할 것. API 상태 표현에 필요한 최소 변경만 허용한다.
- 현재 리뉴얼된 화면 틀과 디렉터리 구조를 유지할 것.
- 필요 없는 리팩터링, 파일 이동, 네이밍 변경을 하지 말 것.
- Backend Response를 Source of Truth로 사용할 것.
- 권한 판단은 Backend에서 수행하고, Frontend는 UX 처리만 담당할 것.
- Backend API 명세에 없는 기능은 구현하지 말 것.
- API 응답 필드명이 기존 프론트 상태명과 다르면 프론트 내부에 매핑 레이어를 둘 것.
- 기존 Mock·Prototype fallback은 API 정상 연동과 회귀 검증이 끝난 범위에서만 제거할 것.
- API 실패를 Mock 또는 Browser 저장소 값으로 성공 처리하지 말 것.
- 새 Mock 데이터를 만들지 말 것.
- 로딩, 성공, 실패, 빈 상태를 모든 API 연동 화면에 반영할 것.

## 금지

- userId 직접 전달 금지
- authorUserId 전달 금지
- role/admin flag 전달 금지
- membership id 직접 전달 금지
- 클라이언트에서 권한 우회 금지
- Backend에 없는 데이터 임의 생성 금지
- API 명세에 없는 query parameter 추가 금지
- API 명세에 없는 request body field 추가 금지
- 임시 teamId, 임시 spaceId 생성 금지
- Backend에 없는 예약 상태, 팀 상태, 참여 상태 생성 금지
- 전체 Space/Team 데이터를 가져온 뒤 Frontend에서 권한 필터링 금지
- API 실패를 성공처럼 처리하거나 localStorage로 보정 금지
- Space/Team API 연동을 이유로 Home React island 컴포넌트 구조나 화면 레이아웃을 대규모 재구성 금지
- 관리자 대시보드 공통 레이아웃 수정 금지
- 기존 CSS 파일 구조를 무시하고 새 거대 CSS 파일 생성 금지

## 인증

Browser에서는 Token 원문을 직접 다루지 않는다.

- Browser → Frontend BFF: Same-Origin Session Cookie 기반 요청
- Frontend BFF → Domain Service: Session의 Access JWT를 `Authorization: Bearer`로 relay
- Access Token / Refresh Token을 HTML, JavaScript, localStorage, sessionStorage에 노출하지 않는다.

- 관리자 대시보드에서 Space/Team 상태를 보여주는 영역이 있다면 기존 관리자 틀 안에서만 연결

## 구현 원칙

- 기존 Space 화면 흐름을 유지한다.
- 화면 구조를 크게 바꾸지 말고, Mock 데이터 표시 영역만 Backend Response 기준으로 치환한다.
- Space와 Team의 소유권, 참여 가능 여부, 관리 가능 여부는 Backend Response 기준으로 처리한다.
- 사용자의 membership, cohort, team role은 Frontend에서 추론하지 않는다.
- 권한 없는 액션은 버튼 숨김, 비활성, 오류 메시지 등 UX만 처리한다.
- 목록, 상세, 생성, 수정, 삭제의 성공/실패 상태를 Backend Response 기준으로 처리한다.
- 새로고침 후 Backend 상태와 UI 상태가 일치해야 한다.

## 데이터 처리 기준

- 공간 목록이 빈 배열이면 빈 상태 UI를 표시한다.
- 팀이 없는 사용자는 팀 없음 상태를 표시한다.
- 삭제되었거나 접근 불가능한 공간/팀은 Backend의 404/403 응답 기준으로 처리한다.
- 예약, 참여, 수정, 삭제 같은 상태 변경은 성공 응답을 받은 뒤 UI를 갱신한다.
- 브라우저 저장소에 Space/Team 상태를 정본으로 저장하지 않는다.
- null, 빈 배열, 빈 문자열, 권한 없음, 삭제된 리소스 상태를 반드시 UI에서 처리한다.

## API 연동 구조

- Space/Team API 호출은 한 곳에서 관리한다.
- `space.js` 안에 fetch 호출을 직접 흩뿌리지 않는다.
- `spaceApi`, `teamApi` 같은 service 단위로 요청 함수를 분리한다.
- 화면 렌더링 함수와 API 호출 함수를 분리한다.
- React 컴포넌트는 화면 구조와 상태 표현을 담당하고, Backend API 호출은 공통 API/helper 계층으로 분리한다.
- 기존 Vanilla JS에서 React로 기능을 옮길 때는 Space/Team 기능 단위로 작게 옮긴다.
- API 응답 DTO와 화면 상태 DTO가 다르면 매핑 함수를 둔다.
- 스타일 클래스명과 API 필드명을 강하게 결합하지 않는다.
- API 에러 메시지는 서버 메시지를 우선 사용하되, 없을 경우 공통 메시지를 사용할 것.

## 관리자 대시보드 연동 시 기준

관리자 대시보드에서 Space/Team 상태를 다룬다면 기존 관리자 레이아웃과 화면 틀을 유지한다.

- HTML: `src/main/resources/templates/pages/manager/managerDashboard.html`
- CSS: `src/main/resources/static/css/managerDashboard.css`
- JS: `src/main/resources/static/js/managerDashboard.js`
- Controller/View 연결:
  - `WebConfig`의 `/manager-dashboard -> pages/manager/managerDashboard`

관리자 관련 금지:

- Browser 저장소의 manager/admin 값으로 권한 판단 금지
- Frontend에서 담당 기수 범위 추론 금지
- 관리자 전용 API에 role/admin flag 전달 금지
- Backend API 없이 UI만 성공 처리 금지
