= Omagotchi Frontend REST API 문서
:toc: left
:toclevels: 3
:source-highlighter: highlight.js
:snippets: {projectdir}/target/generated-snippets

이 문서는 Frontend BFF의 컨트롤러 계약 테스트에서 생성한 요청·응답 문서 조각을 도메인별로 구성합니다.
`./mvnw package`를 실행하면 `target/generated-docs/index.html`에서 완성된 문서를 확인할 수 있습니다.
각 테스트에서 생성한 REST Docs 문서 조각은 `target/generated-snippets`에 저장됩니다.

== 문서 작성 범위

Frontend가 브라우저에서 받는 BFF 요청과 응답 계약을 기록합니다.
내부 서비스의 직접 API 계약은 각 서비스의 API 문서에서 관리합니다.
새 계약 테스트와 문서 조각을 추가하면 도메인별 문서에도 해당 항목을 연결합니다.
현재 문서는 테스트로 검증한 BFF HTTP 계약과 Spring Security의 로그인·로그아웃 계약을 다룹니다.

== 브라우저 세션과 CSRF

브라우저 인증 상태는 JWT를 브라우저 저장소에 보관하지 않고 서버에 저장된 세션과 세션 쿠키로 전달합니다.
문서화 테스트는 세션 쿠키와 서버 측 인증 경계를 전제로 합니다.
실제 보안 필터 체인을 적용한 통합 테스트에서는 상태 변경 요청에 Spring Security CSRF 토큰을 포함합니다.
MockMvc를 단독으로 구성한 컨트롤러 계약 테스트에서는 전체 필터 체인을 실행하지 않으므로 CSRF 검증까지 재현하지 않습니다. 실제 요청에 CSRF가 필요한 경우에만 고정된 테스트 토큰을 문서에 표시합니다.
브라우저에서 로그아웃할 때는 CSRF 토큰을 포함해 `POST /logout`을 호출합니다.

== 공통 문서화 규칙

요청·응답 문서 조각은 `prettyPrint()`로 읽기 쉽게 생성합니다.
`Authorization`, `Cookie`, `Set-Cookie` 헤더와 CSRF 토큰처럼 재사용할 수 있는 인증·세션 값은 실제 값을 기록하지 않고 `[REDACTED]` 또는 테스트에서 정한 고정 자리표시자로 바꿉니다.
액세스 토큰, 리프레시 토큰, 세션 ID, 비밀번호, OTP 같은 비밀값에도 같은 규칙을 적용합니다.
실제 계약에 필요한 헤더와 쿠키의 이름은 남기고 값만 정규화합니다.
